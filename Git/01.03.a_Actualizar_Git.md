# Conceptos clave de Git

Git es un sistema de control de versiones distribuido que permite:

- registrar cambios en archivos
- trabajar en equipo
- recuperar versiones anteriores del proyecto
- mantener un historial completo de modificaciones

---

# Áreas principales de Git

Git trabaja con **tres áreas principales**.

| Área | Descripción |
|-----|-------------|
| **Working Directory** | Archivos que estás editando en tu proyecto |
| **Staging Area (Index)** | Archivos preparados para el siguiente commit |
| **Repository (HEAD)** | Historial de commits del proyecto |

---

# Flujo básico de trabajo

```
Working Directory
        │
        │ git add
        ▼
Staging Area
        │
        │ git commit
        ▼
Repository (HEAD)
```

---

# Flujo completo de trabajo

```
Modificar archivos
        │
        ▼
Working Directory
        │
        │ git add
        ▼
Staging Area
        │
        │ git commit
        ▼
Repository (local)
```

## Configuración

| Comando | Descripción |
|--------|-------------|
| `git config --global user.name "<nombre>"`| configurar el nombre del autor de los commits |
| `git config --global user.email "<mail>"`| configurar el mail del Autor |
| `git config --global init.defaultBranch main`| nombrar a la rama principal "main" |
| `git config --global alias.<nombre> "<comando>"`| si queremos personalizar y simplificar un <comando> llamándolo solo por el alias <nombe> |

> **Importante:** la opción `--global` aplica la configuración a los repositorios del usuario. Normalmente solo es necesario configurarla una vez, salvo que quieras modificarla.

| Comando | Descripción |

### Comprobar cambios

| Comando | Descripción |

# 7. Deshacer cambios

## Quitar archivo del staging

```bash
git restore --staged archivo.txt
```

---

## Deshacer cambios de un archivo

```bash
git restore archivo.txt
```

---

## Volver a un commit anterior

```bash
git reset --hard ID_COMMIT
```

⚠️ Elimina cambios posteriores.

```bash

```

# 11. Diferencia entre CMD, Git CMD y Git Bash

Cuando trabajas con Git en Windows puedes usar diferentes terminales.

## CMD (Command Prompt)

Es la terminal estándar de Windows.

Características:

- no incluye Git por defecto
- usa comandos propios de Windows (`dir`, `cd`, `copy`, etc.)
- puede ejecutar Git si está instalado y añadido al PATH

Ejemplo:

```text
C:\Users\usuario>
```

Ejemplo de uso:

```bash
cd C:\proyectos\mi-repo
git status
```

---

## Git CMD

Es una terminal que se instala junto con **Git for Windows**.

Características:

- es básicamente CMD con Git ya configurado
- incluye variables de entorno necesarias para Git
- maneja correctamente autenticación y herramientas Git

Ejemplo:

```text
C:\Program Files\Git>
```

En la práctica los comandos funcionan igual que en CMD, pero Git suele estar mejor preparado para funcionar sin problemas.

---

## Git Bash

Git Bash es una terminal tipo **Linux/Unix** incluida en Git for Windows.

Permite usar comandos Linux además de Git.

---

## Comparación

| Terminal | Tipo | Ventajas | Uso recomendado |
|--------|--------|--------|--------|
| CMD | Terminal nativa de Windows | Simple | Uso general |
| Git CMD | CMD con Git configurado | Git funciona directamente | Git en Windows |
| Git Bash | Terminal estilo Linux | Comandos Unix + Git | Recomendado para desarrollo |

# 12. Diagrama visual del flujo Git

```text
[Working Directory]
       |
       | git add
       v
[Staging Area]
       |
       | git commit
       v
[Repositorio Local]
       |
       | git push
       v
[Repositorio Remoto]
```

Resumen:

- **Working Directory**: donde editas archivos
- **Staging Area**: donde preparas los cambios
- **Repositorio Local**: donde se guardan los commits
- **Repositorio Remoto**: GitHub, GitLab o servidor remoto

# Comandos para deshacer cambios

| Comando | Descripción |
|--------|-------------|
| `git checkout <rama>` | Cambia a otra rama |
| `git checkout <archivo>` | Restaura un archivo al último commit |
| `git reset` | Mueve el puntero HEAD a otro commit |
| `git restore <archivo>` | Recupera archivos del último commit |
| `git switch <rama>` | Cambia de rama (reemplazo moderno de checkout) |

---

# Git reset

`git reset` permite **mover el puntero HEAD a otro commit**.

Dependiendo del modo puede modificar:

- el repositorio
- el staging area
- el working directory

---

## Modos de git reset

| Modo | Qué modifica | Resultado |
|-----|-------------|-----------|
| `--soft` | HEAD | mantiene staging |
| `--mixed` | HEAD + staging | limpia staging |
| `--hard` | HEAD + staging + working directory | elimina cambios |

---

## Qué ocurre internamente

### git reset --soft

```
Repository (HEAD)  ← cambia
Staging Area       ← sin cambios
Working Directory  ← sin cambios
```

---

### git reset --mixed

```
Repository (HEAD)  ← cambia
Staging Area       ← se vacía
Working Directory  ← sin cambios
```

---

### git reset --hard

```
Repository (HEAD)  ← cambia
Staging Area       ← se vacía
Working Directory  ← se restaura
```

⚠️ Se pierden los cambios no guardados.

---

# Ejemplos

Volver al commit anterior manteniendo cambios:

```bash
git reset --soft HEAD~1
```

Quitar archivo del staging:

```bash
git reset HEAD archivo.txt
```

Eliminar completamente cambios:

```bash
git reset --hard HEAD~1
```

---

# Diferencias entre reset, revert y restore

| Comando | Qué hace | Uso típico |
|-------|-----------|-------------|
| `git restore` | recupera archivos | descartar cambios |
| `git reset` | mueve HEAD | reescribir historial local |
| `git revert` | crea commit inverso | deshacer cambios publicados |

---

# Ejemplos

```bash
git restore archivo.txt
```

```bash
git revert HEAD
```

---

# Nota sobre git checkout

Históricamente `git checkout` hacía varias cosas:

- cambiar ramas
- restaurar archivos
- moverse entre commits

Por eso Git introdujo:

```bash
git switch
git restore
```

# Trabajo con repositorios remotos

Cuando usamos repositorios remotos (GitHub, GitLab, etc.) el flujo se amplía:

```
Editar archivos
      │
      ▼
Working Directory
      │
      │ git add
      ▼
Staging Area
      │
      │ git commit
      ▼

      │
      │ git push
      ▼
Repositorio remoto
```

---

# Diferencia entre fetch y pull

| Comando | Qué hace |
|-------|----------|
| `git fetch` | descarga cambios |
| `git pull` | descarga + integra |

---

# Estados de los archivos en Git

| Estado | Descripción |
|------|-------------|
| **Untracked** | archivo nuevo |
| **Modified** | archivo modificado |
| **Staged** | preparado para commit |
| **Committed** | guardado en el historial |

---

# Flujo de estados

```
Untracked
    │
    │ git add
    ▼
Staged
    │
    │ git commit
    ▼
Committed
    │
    │ modificar archivo
    ▼
Modified
```
