# Vistos en el curso

## Anatomía del comando

```
comando [opciones] [argumentos]
```
* `comando` es lo que quieres ejecutar (`ls`).
* `opciones` modifican el comportamiento (`-l`)
* `argumentos` son los datos sobre los que actúa (`archivo.txt`, `directorio/`)

## Comandos de Orientación

| Comando | Descripción |
|--------|-------------|
| `pwd`| mostrar la ruta absoluta del directorio actual [ejemplo de ruta relativa: cd documentos/] |
| `ls`| ver qué archivos / carpetas hay dentro de la carpeta donde nos encontramos |
| `ls -l`| mostrar los archivos en formato largo |
| `ls -a`| mostrar todos los archivos, incluidos los ocultos |
| `ls -lh`| como -l, pero el tamaño de los archivos aparece en formato "legible por humanos" |

## Comandos de Navegación

| Comando | Descripción |
|--------|-------------|
| `cd <directorio>`| entra en un directorio concreto |
| `cd dir`| desplazarse al directorio inferior indicado (significa "ir a un nivel inferior concreto" ) |
| `cd dir/dir/dir`| desplazarse varios directorios inferiores a la vez |
| `cd ..`| desplazarse al directorio superior al actual (significa "un nivel arriba") |
| `cd ../../../`| desplazarse varios niveles superiores a la vez |
| `cd .`| referenciar al directorio actual |
| `cd ~`| desplazarse directamente a tu directorio personal (home) |

### Comando de Ruta relativa y absoluta

| Comando | Descripción |
|--------|-------------|
| `pwd`| la ruta relativa hace referencia al directorio actual. No empieza por `/` y es más corta y práctica cuando sabes dónde estás. |
| `/`| raíz del sistema |
| `cd /mnt/c/Users/josed`| la ruta absoluta indica la ubicación completa de un archivo o directorio en el sistema de archivos del operativo. Siempre empieza por `/` para representar la raíz del sistema y no depende de dónde estés en ese momento. |

| `/home`| Guarda los archivos personales de los usuarios |
| `/etc`| Contiene la configuración del sistema y sus servicios |
| `/bin`| Contiene comandos y programas básicos del sistema |
| `/usr`| Contiene programas, herramientas y archivos compartidos |
| `/var`| Guarda datos que cambian, como registros (logs) y colas |
| `/tmp`| Almacena archivos temporales que pueden eliminarse automáticamente |
| `/root`| Carpeta personal del administrador (root) |
| `/dev`| Representa dispositivos como discos, terminales y periféricos |
| `/proc`| Muestra información sobre los procesos y el kernel |
| `/sys`| Permite consultar y configurar aspectos del hardware y del kernel |
| `/sbin`| Contiene herramientas de administración del sistema |
| `/media`| Se utiliza para montar dispositivos extraíbles, como USB |
| `/run`| Guarda información temporal de servicios y procesos activos |
| `/srv`| Almacena datos utilizados por servicios, como servidores web |
| `/lib`| Contiene bibliotecas necesarias para programas y componentes del sistema |

### Manipulación

| Comando | Descripción |
|--------|-------------|
| `mkdir <carpeta>` | crear una carpeta en la ruta actual |
| `mkdir -p <ruta>` | crear una carpeta y, si es necesario, sus directorios superiores |
| `rmdir <carpeta>` | eliminar una carpeta vacía |
| `touch <archivo>` | crear un archivo vacío si no existe; si existe, actualizar sus fechas de acceso y modificación |
| `nano <archivo>` | abrir un archivo para editarlo o crearlo si no existe. Guardar con Ctrl + O y Enter; salir con Ctrl + X |
| `cat <archivo>` | mostrar el contenido de un archivo |
| `rm <archivo>` | eliminar un archivo sin enviarlo a la papelera |
| `rm -r <carpeta>` | eliminar una carpeta y todo su contenido, incluidas sus subcarpetas. Utilizar con precaución |
| `rm -ri <carpeta>` | eliminar una carpeta y todo su contenido, incluidas sus subcarpetas, solicitando confirmación durante la eliminación de archivos y directorios. Utilizar con precaución |
| `cp <archivo> <ruta_destino>` | copiar un archivo a otra carpeta, conservando el original |
| `cp <nombre_original> <nombre_copia>` | crear una copia del archivo con otro nombre, conservando el original |
| `cp -r <carpeta> <ruta_destino>` | copiar una carpeta y todo su contenido; si el destino es una carpeta existente, crear una copia dentro de ella, si no existe se crea la carpeta con la copia dentro |
| `cp -a <carpeta> <ruta_destino>` | copiar una carpeta y todo su contenido, incluidos archivos ocultos, permisos, fechas y enlaces simbólicos, preservando sus atributos en la medida de lo posible. Si el destino existe y es una carpeta, crear una copia dentro de ella; si no existe, crear el destino como copia de la carpeta original |
| `cp -i <archivo> <destino>` | copiar un archivo solicitando confirmación antes de sobrescribir uno existente |
| `mv <archivo> <ruta_destino>` | mover un archivo a otra carpeta, eliminándolo de su ubicación original |
| `mv <nombre_actual> <nombre_nuevo>` | renombrar un archivo o carpeta sin crear una copia |
| `mv -i <archivo> <destino>` | mover o renombrar un archivo solicitando confirmación antes de sobrescribir uno existente |
| `df -h` | mostrar el espacio total, utilizado y disponible de los sistemas de archivos montados |
| `du -sh <carpeta>` | mostrar el espacio ocupado por una carpeta y su contenido |

> Ejemplos
> | `cp *.log temporal/` | copiar todos los archivos `.log` de la carpeta actual a `temporal/`, conservando los originales |
> | `mv *.log temporal/` | mover todos los archivos `.log` de la carpeta actual a `temporal/` |
> | `find . -maxdepth 1 -type f -name "*.log" -delete` | eliminar los archivos `.log` de la carpeta actual. Utilizar con precaución |

### Wildcards (Comodines)

| Comodín | Descripción |
|---------|-------------|
| `*` | representar cero o más caracteres en el nombre de archivos o carpetas |
| `?` | representar exactamente un carácter en el nombre de archivos o carpetas |

> * Los **comodines** no son comandos: son patrones que Bash interpreta antes de ejecutar comandos como ls, cp o rm.
> * **Archivos ocultos**: por defecto, * y ? no seleccionan nombres que comienzan por un punto (.), salvo que se modifique la configuración de Bash.
> 
> #### Ejemplos
> 
> | Comando | Descripción |
> |---------|-------------|
> | `ls *.pdf` | mostrar todos los archivos PDF de la carpeta actual |
> | `ls informe*` | mostrar archivos o carpetas cuyos nombres comiencen por `informe` |
> | `ls *informe*` | mostrar archivos o carpetas que contengan `informe` en cualquier posición del nombre |
> | `cp *.txt /tmp/` | copiar todos los archivos terminados en `.txt` a `/tmp/` |
> | `rm *.log` | eliminar todos los archivos terminados en `.log` de la carpeta actual. Utilizar con precaución |
> | `ls archivo?.txt` | mostrar archivos cuyo nombre comience por `archivo` y tenga exactamente un carácter adicional antes de `.txt`, como `archivo1.txt` o `archivoA.txt`, pero no `archivo10.txt` |
> | `ls archivo??.txt` | mostrar archivos cuyo nombre comience por `archivo` y tenga exactamente dos caracteres adicionales antes de `.txt`, como `archivo10.txt` o `archivoAB.txt`, pero no `archivo1.txt` |
> | `ls ?????*` | mostrar archivos y carpetas cuyos nombres tengan cinco o más caracteres |
>  
> * `?????` → exige exactamente 5 caracteres.
> * `*` → permite añadir cero o más caracteres adicionales.

### Listados avanzados

| Comando | Descripción |
|--------|-------------|
| `tree` | mostrar la estructura de carpetas y archivos de la ruta actual en forma de árbol |
| `find` | buscar y mostrar archivos y carpetas de forma recursiva desde la ruta actual |

> #### Ejemplos
> 
> | Comando | Descripción |
> |---------|-------------|
> | `tree -L <numero_niveles>` | mostrar la estructura de carpetas y archivos en forma de árbol, limitando la profundidad al número de niveles indicado |
> | `tree -d` | mostrar únicamente las carpetas en forma de árbol |
> | `find . -name "*.txt"` | buscar archivos y carpetas cuyos nombres terminen en `.txt` desde la ruta actual y sus subcarpetas |
> | `find /home -name "archivo.txt"` | buscar archivos o carpetas llamados exactamente `archivo.txt` dentro de `/home` y sus subcarpetas |
> | `find . -type f` | buscar y mostrar únicamente archivos desde la ruta actual |
> | `find . -type d` | buscar y mostrar únicamente carpetas desde la ruta actual |
> | `find . -iname "*.pdf"` | buscar archivos y carpetas terminados en `.pdf`, sin distinguir mayúsculas y minúsculas |
> | `find . -maxdepth 1 -type f -name "*.log"` | buscar archivos `.log` en la carpeta actual sin entrar en subcarpetas |
> 
> **Importante**:
> - tree puede no venir instalado en Ubuntu. Puedes instalarlo con sudo apt install tree.
> - En find, el punto (.) significa «directorio actual» y las comillas en "*.txt" evitan que Bash expanda el comodín antes de realizar la búsqueda.
> - └───> La diferencia principal es que tree sirve para visualizar la estructura de directorios, mientras que find permite buscar archivos y carpetas aplicando filtros.
> - `find` permite buscar archivos y directorios según diferentes criterios.
> - `-maxdepth 1` limita la búsqueda al directorio indicado, sin entrar en sus subdirectorios.
> - `-type f` selecciona únicamente archivos normales.
> - `-name "*.log"` busca nombres que terminen en `.log`.
> - `-delete` elimina los elementos encontrados sin enviarlos a la papelera.
> - Antes de utilizar `-delete`, ejecutar la misma búsqueda con `-print` para comprobar qué archivos se seleccionarán.

### Lectura de archivos

| Comando | Descripción |
|--------|-------------|
| `cat <archivo>` | mostrar todo el contenido de un archivo directamente en la terminal |
| `less <archivo>` | visualizar el contenido de un archivo de forma interactiva, permitiendo desplazarse hacia arriba y abajo sin modificarlo. Pulsar `q` para salir |
| `more <archivo>` | visualizar el contenido de un archivo página a página, principalmente hacia adelante. Pulsar `Espacio` para avanzar y `q` para salir |
| `head <archivo>` | mostrar las primeras 10 líneas de un archivo |
| └───> `head -n <numero_lineas> <archivo>` | mostrar las primeras líneas de un archivo, indicando cuántas se desean visualizar |
| `tail <archivo>` | mostrar las últimas 10 líneas de un archivo |
| └───> `tail -f <archivo>` | mostrar las últimas líneas de un archivo y continuar visualizando en tiempo real las nuevas líneas que se añadan. Pulsar `Ctrl + C` para salir. Ideal para leer `logs` |

> #### Diferencias importantes:
> - cat es útil para archivos pequeños, porque muestra todo el contenido de una vez.
> - less es preferible para archivos grandes, ya que permite navegar cómodamente y buscar texto escribiendo /palabra.
> - more es parecido a less, pero generalmente ofrece menos posibilidades de navegación.
> - head y tail permiten consultar únicamente el principio o el final de un archivo.
> - tail -f es especialmente útil para supervisar registros de aplicaciones y detectar errores mientras se producen.

### Búsqueda y recuento

| Comando | Descripción |
|--------|-------------|
| `grep <palabra> <archivo>` | buscar una palabra o patrón en un archivo y mostrar las líneas que lo contienen, distinguiendo mayúsculas y minúsculas |
| `grep -i <palabra> <archivo>` | buscar una palabra o patrón en un archivo sin distinguir mayúsculas y minúsculas |
| `grep -r <palabra> <ruta>` | buscar una palabra o patrón de forma recursiva en los archivos de una carpeta y todas sus subcarpetas |
| `wc <archivo>` | contar el número de líneas, palabras y bytes de un archivo |
| `wc -l <archivo>` | contar el número de saltos de línea de un archivo |
| `wc -w <archivo>` | contar el número de palabras de un archivo |
| `wc -c <archivo>` | contar el número de bytes de un archivo |
| `wc -cl <archivo>` | contar el número de líneas (saltos de línea) y bytes de un archivo |

> #### Ejemplos
> | Comando | Descripción |
> |---------|-------------|
> | `grep -n "error" archivo.log` | buscar las líneas que contienen `error` y mostrar su número de línea |
> | `grep -v "error" archivo.log` | mostrar las líneas que no contienen `error` |
> | `grep -c "error" archivo.log` | contar las líneas que contienen `error`, no el número total de apariciones |
> | `grep -w "error" archivo.log` | buscar `error` como palabra completa, evitando coincidencias como `errores` |
> | `grep -rin "error" .` | buscar `error` en los archivos de la carpeta actual y sus subcarpetas, sin distinguir mayúsculas y mostrando los números de línea |
> | `wc -m archivo.txt` | contar el número de caracteres de un archivo |
> | `wc -L archivo.txt` | mostrar la longitud de la línea más larga de un archivo |
>
> #### Muy útil
>
> - `grep -i "error" archivo.log | wc -l`
> Esto cuenta cuántas líneas del archivo contienen error, sin distinguir mayúsculas y minúsculas. Es especialmente práctico para analizar registros de aplicaciones.
>

### Redirecciones y pipes (concatenaeión)

| Comando | Descripción |
|--------|-------------|
| `>` | redirigir la salida de un comando a un archivo, creándolo si no existe o sobrescribiendo su contenido si ya existe |
| `> /dev/null` | descartar la salida estándar de un comando |
| `>>` | redirigir la salida de un comando al final de un archivo, creándolo si no existe y conservando su contenido anterior |
| `<` | utilizar el contenido de un archivo como entrada estándar de un comando |
| `\|` | conectar la salida estándar de un comando con la entrada estándar de otro, permitiendo encadenar comandos |
| `>> archivo.log 2>&1` | añadir al archivo tanto la salida normal como los errores |
| `2>` | redirigir los mensajes de error de un comando a un archivo, sobrescribiéndolo si existe |
| `2>/dev/null` | descartar los mensajes de error de un comando, manteniendo su código de salida |
| `2>>` | añadir los mensajes de error de un comando al final de un archivo, conservando su contenido anterior |
| `2>&1` | redirigir los mensajes de error al mismo destino que la salida estándar |
| `&>` | redirigir tanto la salida estándar como los mensajes de error a un archivo, sobrescribiéndolo si existe |
| `tee <archivo>` | mostrar la salida por pantalla y guardarla en un archivo, sobrescribiéndolo |
| `tee -a <archivo>` | mostrar la salida por pantalla y añadirla al final de un archivo |
| `exec >> <archivo.log> 2>&1` | redirigir las salidas posteriores del script al archivo indicado |

> #### Ejemplos
> | Comando | Descripción |
> |---------|-------------|
> | `echo "Hola mundo" > archivo.txt` | escribir un texto en un archivo, creándolo si no existe o sobrescribiendo su contenido anterior |
> | `echo "Nueva línea" >> archivo.txt` | añadir una línea de texto al final de un archivo sin eliminar su contenido anterior |
> | `tree >> estructura.txt` | guardar la estructura de carpetas y archivos al final de un archivo, conservando su contenido anterior |
> | `sort < archivo.txt` | ordenar alfabéticamente las líneas de un archivo y mostrar el resultado en la terminal, sin modificar el original |
> | `cat archivo.txt \| grep "error" \| wc -w` | mostrar el contenido de un archivo, filtrar las líneas que contienen `error` y contar las palabras de esas líneas |
> | `ls > listado.txt` | guardar el listado de archivos y carpetas en un archivo, sobrescribiéndolo si ya existe |
> | `ls >> listado.txt` | añadir el listado de archivos y carpetas al final de un archivo existente |
> | `sort < archivo.txt > ordenado.txt` | ordenar las líneas de un archivo y guardar el resultado en otro |
> | `grep "error" archivo.log > errores.txt` | buscar las líneas que contienen `error` y guardar los resultados en otro archivo |
> | `comando 2> errores.log` | ejecutar un comando y guardar sus mensajes de error en un archivo |
> | `comando > salida.log 2>&1` | guardar tanto la salida normal como los mensajes de error de un comando en un mismo archivo |
> | `cp origen.txt destino.txt 2>/dev/null` | intentar copiar un archivo ocultando los mensajes de error |
> | `cp origen.txt destino.txt 2>/dev/null \|\| echo "ERROR"` | mostrar un mensaje personalizado si falla la copia |
> | `echo "Proceso correcto" \| tee -a proceso.log` | mostrar y guardar un mensaje en el registro |
>
> - Las redirecciones (>, >>, <) sirven para controlar de dónde vienen los datos y adónde van, mientras que las tuberías (|) permiten procesar la salida de un comando con otro

**Importante:**
- `2>/dev/null` oculta el mensaje de error, pero no hace que el comando tenga éxito.
- `>` sobrescribe el contenido anterior, mientras que `>>` añade información.
- `2>&1` envía los errores al mismo destino que la salida estándar.
- `tee -a` permite registrar información y mostrarla simultáneamente por pantalla.

### Variables de entorno

| Comando | Descripción |
|--------|-------------|
| `<NOMBRE>=<valor>` | crear o asignar un valor a una variable de la sesión actual de Bash, sin espacios alrededor del signo `=` |
| `echo $<NOMBRE>` | mostrar el valor almacenado en una variable |
| `export <NOMBRE>` | exportar una variable existente para que esté disponible en los procesos hijos |
| `export <NOMBRE>=<valor>` | crear o modificar una variable y exportarla a los procesos hijos |
| `printenv` | mostrar todas las variables de entorno exportadas |
| `printenv <NOMBRE>` | mostrar el valor de una variable de entorno exportada |
| `env` | mostrar las variables de entorno del proceso |
| `unset <NOMBRE>` | eliminar una variable de la sesión actual, esté exportada o no |
| `set` | mostrar las variables y funciones definidas en la sesión actual de Bash, entre otra información |

> Conviene distinguir tres conceptos, porque en Bash una variable local, una variable de shell y una variable de entorno no son exactamente lo mismo.
> | Tipo | Descripción |
> |------|-------------|
> | Variable de shell | existe en la sesión actual de Bash, pero no se transmite automáticamente a los procesos hijos |
> | Variable de entorno | se exporta mediante `export` y está disponible para los procesos hijos, pero no permanece automáticamente al cerrar la terminal |
> | Variable local de función | se declara con `local` dentro de una función y su ámbito queda limitado a esa función y a las funciones que esta invoque |
> | Archivo habitual de configuración interactiva | `~/.bashrc` | `~/.zshrc` |
> | Aplicar configuración | `source ~/.bashrc` | `source ~/.zshrc` |
> | Consultar intérprete actual | `ps -p $$ -o comm=` | `ps -p $$ -o comm=` |
> | Archivo habitual de historial | `~/.bash_history` | `~/.zsh_history` |

> #### Ejemplos
> | Comando | Descripción |
> |---------|-------------|
> | `NOMBRE="Jose"` | crear una variable de shell llamada `NOMBRE` con el valor `Jose` |
> | `echo $NOMBRE` | mostrar el valor de la variable `NOMBRE` |
> | `export NOMBRE="Jose"` | crear una variable de entorno que podrán heredar los procesos hijos |
> | `export NOMBRE` | exportar una variable previamente definida |
> | `printenv NOMBRE` | mostrar el valor de `NOMBRE` si está exportada |
> | `unset NOMBRE` | eliminar la variable `NOMBRE` de la sesión actual |
> | `echo $HOME` | mostrar la carpeta personal del usuario |
> | `echo $PATH` | mostrar las rutas donde el sistema busca comandos ejecutables |
> | `echo $USER` | mostrar el nombre del usuario almacenado en la variable `USER` |
> | `echo $SHELL` | mostrar la ruta del shell configurado para el usuario, según la variable `SHELL` |
>
> #### Cómo hacer permanentes las variables de entorno
> - Cuando utilizamos export, la variable queda disponible en la sesión actual y en los procesos hijos, pero se pierde al cerrar la sesión si no se guarda en un archivo de configuración.
> - En Ubuntu y WSL, uno de los archivos habituales para guardar estas variables es `~/.bashrc`, que Bash ejecuta al iniciar una sesión interactiva no configurada como login shell.
> 
> | Comando | Descripción |
> |---------|-------------|
> | `export NOMBRE="valor"` | crear una variable de entorno temporal, disponible en la sesión actual y sus procesos hijos |
> | `nano ~/.bashrc` | abrir el archivo de configuración de Bash para añadir variables de entorno permanentes |
> | `source ~/.bashrc` | aplicar en la terminal actual los cambios realizados en `.bashrc`, sin necesidad de abrir una nueva terminal |
> | `echo "$NOMBRE"` | mostrar el valor de una variable para comprobar que se ha configurado correctamente |
> | `printenv NOMBRE` | comprobar el valor de una variable de entorno exportada |
> 
> **Importante:**
> - `export` permite que los procesos hijos hereden una variable de entorno.
> - Las variables creadas en una terminal no se transfieren automáticamente a otras terminales abiertas.
> - Guardar una variable en `.bashrc` o `.zshrc` permite volver a definirla al iniciar nuevas sesiones interactivas correspondientes.
> - Aunque la terminal utilice Zsh, un script con `#!/bin/bash` puede ejecutarse mediante Bash.

## Administración del sistema (System Admin)

### Tipos de permisos y usuarios

| Permiso | Archivo | Directorio |
|---------|---------|------------|
| `r` | permitir leer el contenido | permitir listar sus entradas |
| `w` | permitir modificar el contenido | permitir crear, eliminar o renombrar entradas, normalmente junto con `x` |
| `x` | permitir ejecutar el archivo | permitir acceder o atravesar el directorio |

| Usuario | Descripción |
|---------|-------------|
| `u` (user) | propietario |
| `g` (group) | grupo propietario |
| `o` (others) | otros usuarios |
| `a` (all) | todos los usuarios |

### Visualización de permisos

| Comando | Descripción |
|---------|-------------|
| `ls -l <archivo>` | mostrar los permisos, propietario y grupo de un archivo |
| `ls -ld <carpeta>` | mostrar los permisos de una carpeta |

**Anatomía:** `[-][rw-][r--][r--]`

| Bloque | Descripción |
|--------|-------------|
| `-` | tipo de archivo (`-` archivo, `d` directorio, `l` enlace) |
| `rw-` | propietario: lectura y escritura |
| `r--` | grupo: solo lectura |
| `r--` | otros: solo lectura |

### Modificación de permisos (`chmod`)

**Modo simbólico:**

| Comando | Descripción |
|---------|-------------|
| `chmod u+x <archivo>` | añadir ejecución al propietario |
| `chmod u-x <archivo>` | quitar ejecución al propietario |
| `chmod g+w <archivo>` | añadir escritura al grupo |
| `chmod o-r <archivo>` | quitar lectura a otros usuarios |
| `chmod a+x <archivo>` | añadir ejecución a todos |

**Modo octal:** `r = 4`, `w = 2`, `x = 1`, `- = 0`

**Permisos Linux en unidades Windows (WSL)**
En WSL, los archivos ubicados en `/mnt/c/` pueden no conservar los permisos modificados mediante `chmod`.
> **Solución:**
> 1. Editar `/etc/wsl.conf` con `sudo nano /etc/wsl.conf`.
> 2. Añadir la siguiente configuración:
>   [automount]
>   options = "metadata"
> 3. Reiniciar WSL desde PowerShell mediante `wsl --shutdown`.
> 4. Comprobar la configuración con `mount | grep ' on /mnt/c '`.
> 5. Verificar los permisos mediante `chmod 644 archivo.txt` y `ls -l archivo.txt`.

**Importante:** los permisos Linux no sustituyen los permisos NTFS de Windows.

| Comando | Descripción |
|---------|-------------|
| `chmod 700 <carpeta>` | permitir únicamente al propietario acceder y gestionar la carpeta |
| `chmod 755 <archivo>` | propietario: todos los permisos; resto: lectura y ejecución |
| `chmod 744 <archivo>` | propietario: todos los permisos; resto: solo lectura |
| `chmod 644 <archivo>` | propietario: lectura y escritura; resto: solo lectura |
| `chmod 600 <archivo>` | solo propietario: lectura y escritura |
| `chmod -R <permisos> <carpeta>` | modificar los permisos de una carpeta y su contenido de forma recursiva. Utilizar con precaución |

### Cambiar propietario y grupo (`chown`)

| Comando | Descripción |
|---------|-------------|
| `sudo chown <usuario> <archivo>` | cambiar el usuario propietario |
| `sudo chown <usuario>:<grupo> <archivo>` | cambiar el propietario y el grupo |
| `sudo chown :<grupo> <archivo>` | cambiar únicamente el grupo |
| `sudo chown -R <usuario>:<grupo> <carpeta>` | cambiar propietario y grupo de forma recursiva |

> - **Importante**:
> - `sudo` permite ejecutar comandos con privilegios de administrador, siempre que tu usuario esté autorizado.
> - Los permisos se representan siempre en orden `rwx`.
> - `-rw-r--r--` representa un archivo normal con permisos `644`.
> - `drwxr-xr-x` representa un directorio con permisos `755`.
> - El primer carácter indica el tipo de elemento y no forma parte de los permisos octales.
> - Modificar permisos con `chmod` no cambia el propietario del archivo.

## Máscara de permisos (`umask`)

La máscara `umask` determina qué permisos se eliminan por defecto al crear archivos y directorios.

| Comando | Descripción |
|---------|-------------|
| `umask` | mostrar la máscara de permisos actual |
| `umask -S` | mostrar la máscara en formato simbólico |
| `umask 0022` | establecer la máscara para quitar escritura al grupo y a otros usuarios |
| `umask 0000` | establecer una máscara que no elimine ningún permiso |
| `umask 0077` | establecer una máscara que elimine todos los permisos al grupo y a otros usuarios |

### Anatomía de la máscara

> **Ejemplo:** `0022`
> | Dígito | Descripción |
> |--------|-------------|
> | `0` | permisos especiales (setuid, setgid y sticky bit) |
> | `0` | propietario: no quitar permisos |
> | `2` | grupo: quitar escritura (`w`) |
> | `2` | otros: quitar escritura (`w`) |

### Permisos resultantes

| Tipo | Permisos base | umask `0022` | Resultado | Visualización con `ls -l` |
|------|---------------|--------------|-----------|-----------|
| Archivos | `666` (`rw-rw-rw-`) | `022` | `644` | (`-rw-r--r--`) |
| Directorios | `777` (`rwxrwxrwx`) | `022` | `755` | (`drwxr-xr-x`) |

> **Importante:**
> - Los archivos parten normalmente de `666`, sin permisos de ejecución.
> - Los directorios parten normalmente de `777`.
> - `umask` elimina permisos, no los añade.
> - El cambio mediante `umask 0000` afecta a la sesión actual y a los procesos hijos, pero no queda guardado automáticamente para futuras sesiones.

### Superusuario (`sudo`)

| Comando | Descripción |
|---------|-------------|
| `sudo <comando>` | ejecutar un comando con privilegios de administrador (root). Normalmente solicita la contraseña del usuario actual |
| `sudo -i` | iniciar una sesión de terminal como superusuario (root) |
| `whoami` | mostrar el nombre del usuario actual |
| `sudo whoami` | comprobar que el comando se ejecuta como superusuario (`root`) |
| `exit` | salir de la sesión de superusuario y volver al usuario anterior |

> **Importante**:
> - sudo solo funciona si el usuario tiene permisos para utilizarlo.
> - Al introducir la contraseña, no aparecen caracteres en pantalla, ni siquiera asteriscos.
> - No siempre solicita contraseña, porque puede recordar temporalmente la autenticación.
> - Utilizar sudo con precaución, ya que permite modificar archivos y configuraciones críticas del sistema.

### Trabajos (Jobs)

Los trabajos (jobs) son procesos ejecutados desde una terminal que pueden estar en primer plano, segundo plano o suspendidos.

| Comando | Descripción |
|---------|-------------|
| `jobs` | mostrar los trabajos activos o suspendidos de la sesión actual |
| `jobs -l` | mostrar los trabajos de la sesión actual, incluyendo sus PID |
| `kill <PID>` | solicitar la finalización de un proceso mediante su identificador (PID) |
| `kill %<Job_ID>` | solicitar la finalización de un trabajo mediante su identificador |
| `kill -9 <PID>` | forzar la finalización inmediata de un proceso, sin permitirle realizar una limpieza ordenada. Utilizar con precaución |
| `sleep <segundos>` | suspender la ejecución del proceso durante el tiempo indicado |
| `sleep <segundos> &` | ejecutar una espera en segundo plano, permitiendo seguir utilizando la terminal |
| `Ctrl + C` | interrumpir el proceso que se ejecuta en primer plano |
| `Ctrl + Z` | suspender el proceso que se ejecuta en primer plano |
| `bg %<Job_ID>` | reanudar un trabajo suspendido en segundo plano |
| `fg %<Job_ID>` | traer un trabajo al primer plano |

> Ejemplos
> | Comando | Descripción |
> |---------|-------------|
> | `sleep 60` | esperar 60 segundos antes de continuar utilizando la terminal |
> | `sleep 60 &` | ejecutar una espera de 60 segundos en segundo plano |
> | `jobs` | consultar los trabajos activos o suspendidos |
> | `fg %1` | traer al primer plano el trabajo número 1 |
> | `bg %1` | reanudar en segundo plano el trabajo número 1, si está suspendido |
> | `kill %1` | solicitar la finalización del trabajo número 1 |
> | `kill -9 1234` | forzar la finalización del proceso cuyo PID sea 1234 |

> **Importante**:
> - `kill` envía por defecto la señal SIGTERM (15), que permite al proceso finalizar ordenadamente.
> - `kill -9` envía SIGKILL, que fuerza su terminación y conviene reservar para procesos que no responden.
> - `jobs` muestra los trabajos gestionados por la terminal actual, mientras que `ps aux` permite consultar procesos del sistema más allá de esos trabajos.

### Historial

### Historial de comandos (History)

El historial permite consultar, buscar y reutilizar comandos ejecutados anteriormente.

#### Bash

| Comando | Descripción |
|---------|-------------|
| `history` | mostrar el historial de comandos |
| `history 10` | mostrar los últimos 10 comandos |
| `history -c` | borrar el historial de la sesión actual almacenado en memoria |
| `history -w` | guardar el historial actual en `~/.bash_history`, sobrescribiendo el contenido anterior |
| `history -a` | añadir al archivo de historial los comandos nuevos de la sesión actual |
| `!!` | volver a ejecutar el último comando utilizado |
| `!<id_orden>` | volver a ejecutar un comando del historial mediante su número identificador |
| `!<comando>` | volver a ejecutar el comando más reciente que comience por el texto indicado |
| `\!` | interpretar el signo `!` de forma literal, evitando la expansión del historial |
| `Ctrl + R` | buscar comandos anteriores de forma interactiva en el historial |
| `cat ~/.bash_history` | mostrar el historial guardado en el archivo de Bash |

#### Zsh

| Comando | Descripción |
|---------|-------------|
| `history` | mostrar el historial de comandos |
| `history -10` | mostrar los últimos 10 comandos |
| `history 1800` | mostrar el historial desde el evento número 1800 |
| `history -n 10` | mostrar el historial desde el evento número 10, sin mostrar los números de evento |
| `fc -p` | iniciar un historial privado temporal, dejando de mostrar el historial anterior |
| `fc -P` | recuperar el historial anterior después de utilizar `fc -p` |
| `!!` | volver a ejecutar el último comando utilizado |
| `!<id_orden>` | volver a ejecutar un comando del historial mediante su número identificador |
| `!<comando>` | volver a ejecutar el comando más reciente que comience por el texto indicado |
| `\!` | interpretar el signo `!` de forma literal, evitando la expansión del historial |
| `Ctrl + R` | buscar comandos anteriores de forma interactiva en el historial |
| `cat ~/.zsh_history` | mostrar el historial guardado en el archivo habitual de Zsh |

> **Importante:**
> - **Bash:** `history 10` muestra los últimos 10 comandos.
> - **Zsh:** `history -10` muestra los últimos 10 comandos.
> - **Bash:** `history -c` borra el historial de la sesión actual en memoria, pero no necesariamente el archivo persistente.
> - **Zsh:** `fc -p` inicia un historial privado; no elimina definitivamente el historial anterior.
> - **Archivos:** Bash utiliza normalmente `~/.bash_history` y Zsh `~/.zsh_history`, aunque ambos pueden configurarse para utilizar otras rutas.
> - **Precaución:** los comandos recuperados mediante `!!` o `!<comando>` pueden ejecutarse inmediatamente.

> Ejemplos
> | Comando | Descripción |
> |---------|-------------|
> | `!25` | volver a ejecutar el comando número 25 del historial |
> | `!git` | volver a ejecutar el último comando que comience por `git` |
> | `sudo !!` | volver a ejecutar el último comando anteponiendo `sudo` |
> | `history \| grep "git"` | buscar comandos que contengan `git` en el historial |
> | `echo \!` | mostrar el carácter `!` literalmente |

> **Importante**:
> - Los comandos !! y !<comando> se ejecutan directamente, por lo que conviene utilizarlos con precaución.

### Alias

Los alias permiten crear abreviaturas para ejecutar comandos de forma más rápida.

| Comando | Descripción |
|---------|-------------|
| `alias` | mostrar todos los alias definidos en la sesión actual |
| `alias <nombre>='<comando>'` | crear un alias temporal para ejecutar un comando mediante otro nombre, sin espacios alrededor de `=` |
| `unalias <nombre>` | eliminar un alias de la sesión actual |
| `nano ~/.bashrc` | abrir el archivo de configuración de Bash para guardar alias de forma permanente |
| `source ~/.bashrc` | aplicar los cambios realizados en `.bashrc` sin reiniciar la terminal |

> Ejemplos
> | Comando | Descripción |
> |---------|-------------|
> | `alias ll='ls -la'` | crear el alias `ll` para mostrar archivos, incluidos los ocultos, con sus detalles |
> | `alias gs='git status'` | crear el alias `gs` para consultar el estado del repositorio Git |
> | `alias actualizar='sudo apt update && sudo apt upgrade'` | crear un alias para actualizar los paquetes del sistema |
> | `alias gitramas='git log --oneline --decorate --graph --all'` | crear un alias de Bash para visualizar gráficamente el historial de ramas de Git, ejecutándolo mediante `gitramas` |
> | `unalias gs` | eliminar el alias `gs` de la sesión actual |

**Importante:**
- **Temporal:** los alias creados directamente en la terminal desaparecen al cerrar la sesión.
- **Permanente:** añadir el alias al archivo `~/.bashrc` para cargarlo automáticamente al abrir nuevas sesiones interactivas de Bash.
- **Activación:** ejecutar `source ~/.bashrc` para aplicar los cambios inmediatamente.
- **Sintaxis:** no dejar espacios alrededor de `=` ni utilizar espacios en los nombres de alias de Bash.

#### Alias propios de Git

Git permite crear alias de sus subcomandos para ejecutarlos mediante `git <alias>`, sin necesidad de modificar `.bashrc`.

| Comando | Descripción |
|---------|-------------|
| `git config --global alias.ramas 'log --oneline --decorate --graph --all'` | crear un alias permanente de Git llamado `ramas` para visualizar gráficamente el historial de commits y ramas |
| `git ramas` | ejecutar el alias anterior y visualizar el historial de Git |
| `git config --global --get-regexp '^alias\.'` | mostrar los alias de Git definidos en la configuración global |
| `git config --global --unset alias.ramas` | eliminar el alias global `ramas` de Git |
| `nano ~/.gitconfig` | abrir el archivo de configuración global de Git donde se guardan los alias creados con `--global` |

> Ejemplos
> | Comando | Descripción |
> |---------|-------------|
> | `git config --global alias.lg "log --graph --decorate --pretty=format:'%C(auto)%h%d %s %C(black)%C(bold)%cr' --all --abbrev-commit"` | crear el alias `git lg` para visualizar el historial de commits en forma de árbol, mostrando ramas, mensajes y antigüedad de cada commit con colores |
> | └───> `git lg` | visualizar el historial gráfico de commits y ramas |
> | `git config --global alias.lgg "log --graph --decorate --pretty=format:'%C(auto)%h%d %s %C(black)%C(bold)%cr' --all --abbrev-commit --stat"` | crear el alias `git lgg` para visualizar el mismo historial, añadiendo estadísticas de archivos modificados, líneas añadidas y eliminadas |
> | └───> `git lgg` | visualizar el historial gráfico de commits y ramas, incluyendo estadísticas de cambios |
> 
> - No necesitas ejecutar source ~/.bashrc para estos alias: Git los reconoce directamente desde su configuración.

**Diferencias:**
- **Alias de Bash:** se ejecutan directamente, por ejemplo, `gitramas`. Los permanentes pueden guardarse en `~/.bashrc`.
- **Alias de Git:** se ejecutan precedidos de `git`, por ejemplo, `git ramas`. Los definidos con `--global` se guardan normalmente en `~/.gitconfig`.
- **Recomendación:** utilizar alias propios de Git para abreviar subcomandos de Git y alias de Bash para abreviar comandos generales de Linux.

## Scripting

### Scripts de Bash

Un **script** es un archivo de texto que contiene instrucciones y comandos que se ejecutan secuencialmente para automatizar tareas.

### Estructura básica

| Elemento | Descripción |
|----------|-------------|
| `#!/bin/bash` | shebang: indicar que el script debe interpretarse con Bash |
| `# <comentario>` | añadir comentarios que no se ejecutan |
| `<comando>` | ejecutar instrucciones de Linux dentro del script |
| `<VARIABLE>=<valor>` | definir una variable, sin espacios alrededor de `=` |
| `echo "$VARIABLE"` | mostrar el valor de una variable |
| `$(<comando>)` | ejecutar un comando y sustituir la expresión por su salida (sustitución de comandos) |
| `$((<operacion>))` | realizar operaciones aritméticas y devolver el resultado |
| `let "<operacion>"` | realizar operaciones aritméticas sobre variables de Bash |

> Ejemplo de script
> Crear un archivo llamado `script.sh`:

```
    #!/bin/bash

    # Definir variables
    NOMBRE="Jose"
    NUMERO=5

    # Mostrar información
    echo "Hola $NOMBRE"

    # Sustitución de comandos
    FECHA=$(date)
    echo "Fecha actual: $FECHA"

    # Operaciones aritméticas
    RESULTADO=$((NUMERO + 10))
    echo "Resultado: $RESULTADO"

    # Operación mediante let
    let "NUMERO=NUMERO+1"
    echo "Nuevo número: $NUMERO"
```

### Ejecución de scripts

| Comando | Descripción |
|---------|-------------|
| `nano script.sh` | crear o editar un script de Bash |
| `bash script.sh` | ejecutar un script mediante Bash, sin necesidad de permisos de ejecución |
| `chmod +x script.sh` | conceder permiso de ejecución al script |
| `./script.sh` | ejecutar el script desde la carpeta actual, utilizando su shebang |
| `bash -n script.sh` | comprobar la sintaxis del script sin ejecutarlo |
| `bash -x script.sh` | ejecutar el script mostrando las instrucciones procesadas para facilitar su depuración |

### Diferencias entre operaciones

| Sintaxis | Descripción | Ejemplo |
|----------|-------------|---------|
| `$(...)` | ejecutar un comando y capturar su salida | `FECHA=$(date)` |
| `$((...))` | calcular una expresión aritmética y obtener su resultado | `TOTAL=$((5 + 3))` |
| `let` | realizar una operación aritmética y asignar su resultado | `let "TOTAL=5+3"` |

> **Importante:**
> - Los scripts de Bash suelen utilizar la extensión `.sh`, aunque no es obligatoria.
> - El shebang debe aparecer en la primera línea para indicar el intérprete cuando el archivo se ejecuta directamente.
> - `$(...)` no es una interpolación genérica, sino una sustitución de comandos.
> - `$((...))` trabaja principalmente con números enteros.
> - `./script.sh` requiere permisos de ejecución; `bash script.sh` no.
> - Para operaciones aritméticas, suele ser preferible utilizar `$((...))` en lugar de `let`.

### Lectura de datos

Permitir que un script muestre mensajes y solicite información al usuario durante su ejecución.

| Comando | Descripción |
|---------|-------------|
| `echo "<texto>"` | mostrar un mensaje o el valor de una variable en la terminal |
| `read <variable>` | solicitar un dato al usuario y almacenarlo en una variable |
| `read -p "<mensaje>" <variable>` | mostrar un mensaje y solicitar un dato al usuario, almacenándolo en una variable |
| `read -s <variable>` | solicitar un dato sin mostrar los caracteres introducidos, útil para contraseñas |
| `read -s -p "<mensaje>" <variable>` | mostrar un mensaje y solicitar un dato ocultando los caracteres introducidos |
| `read -r <variable>` | leer un dato sin interpretar las barras invertidas (`\`) como caracteres especiales |

> Ejemplos
> | Comando | Descripción |
> |---------|-------------|
> | `echo "Hola mundo"` | mostrar el mensaje `Hola mundo` |
> | `read NOMBRE` | solicitar un nombre y guardarlo en la variable `NOMBRE` |
> | `read -p "Introduce tu nombre: " NOMBRE` | solicitar un nombre mostrando un mensaje |
> | `read -s -p "Introduce tu contraseña: " CLAVE` | solicitar una contraseña ocultando los caracteres introducidos |
> | `echo "$NOMBRE"` | mostrar el nombre introducido anteriormente |

### Argumentos y parámetros

Los argumentos permiten pasar datos a un script en el momento de ejecutarlo, haciendo que su comportamiento sea dinámico.

| Parámetro | Descripción |
|-----------|-------------|
| `$0` | mostrar el nombre o ruta utilizada para ejecutar el script |
| `$1` | obtener el primer argumento recibido |
| `$2` | obtener el segundo argumento recibido |
| `$3` | obtener el tercer argumento recibido |
| `${10}` | obtener el décimo argumento recibido |
| `$#` | mostrar el número de argumentos recibidos |
| `"$@"` | representar todos los argumentos recibidos, conservando cada uno como elemento independiente |
| `"$*"` | representar todos los argumentos recibidos como una única cadena |
| `$?` | mostrar el código de salida del último comando ejecutado (`0` normalmente indica éxito) |

#### Cómo pasar argumentos a un script

**Ejecutar:**
```
    bash script.sh Jose 30 Sevilla
```

**Contenido de `script.sh`:**
```
    #!/bin/bash

    echo "Script: $0"
    echo "Nombre: $1"
    echo "Edad: $2"
    echo "Ciudad: $3"
    echo "Número de argumentos: $#"
    echo "Todos los argumentos: $@"
```

**Resultado:**

    Script: script.sh
    Nombre: Jose
    Edad: 30
    Ciudad: Sevilla
    Número de argumentos: 3
    Todos los argumentos: Jose 30 Sevilla

> **Importante:**
> - Los argumentos se separan mediante espacios al ejecutar el script.
> - Si un argumento contiene espacios, utilizar comillas: `bash script.sh "Jose Diaz" 30 Sevilla`.
> - `$0` no cuenta como argumento dentro de `$#`.
> - Utilizar `"$@"` cuando sea necesario procesar todos los argumentos conservando sus separaciones.
> - `read` solicita datos durante la ejecución, mientras que `$1`, `$2`, etc., reciben datos al iniciar el script.

#### Formatos de fecha y hora

| Comando | Descripción |
|---------|-------------|
| `date +%Y-%m-%d` | obtener la fecha en formato año-mes-día |
| `date +%H:%M:%S` | obtener la hora en formato HH:MM:SS |
| `date +%T` | obtener la hora en formato HH:MM:SS |
| `date '+%Y-%m-%d %H:%M:%S'` | obtener fecha y hora |
| `date +%Y-%m-%d_%H-%M-%S` | generar una fecha y hora apropiadas para nombres de archivos |

> **Importante:**
> - `%Y` representa el año, `%m` el mes y `%d` el día.
> - `%H` representa la hora, `%M` los minutos y `%S` los segundos.
> - Evitar `/` en los nombres de archivos porque Linux lo interpreta como separador de directorios.
> - `$(date ...)` ejecuta el comando y permite almacenar su resultado en una variable.

## Condicionales

Los condicionales permiten ejecutar diferentes instrucciones según se cumpla o no una condición.

| Estructura | Descripción |
|------------|-------------|
| `if [ <condición> ]; then ... fi` | ejecutar instrucciones si se cumple una condición |
| `elif [ <condición> ]; then` | comprobar una condición alternativa si las anteriores no se cumplen |
| `else` | ejecutar instrucciones cuando ninguna condición anterior se cumple |
| `fi` | finalizar una estructura condicional `if` |
| `case <variable> in ... esac` | ejecutar diferentes instrucciones según el valor de una variable |
| `*)` | establecer el caso por defecto cuando ninguna opción anterior coincide |
| `;;` | finalizar una alternativa dentro de `case` |

### Operadores

#### Comparación numérica

| Operador | Descripción |
|----------|-------------|
| `-eq` | igual a (equal) |
| `-ne` | distinto de (not equal) |
| `-gt` | mayor que (greater than) |
| `-ge` | mayor o igual que (greater or equal) |
| `-lt` | menor que (less than) |
| `-le` | menor o igual que (less or equal) |

#### Comparación de cadenas de texto

| Operador | Descripción |
|----------|-------------|
| `=` | comprobar si dos cadenas son iguales |
| `==` | comprobar si dos cadenas son iguales (en Bash) |
| `!=` | comprobar si dos cadenas son diferentes |
| `-z` | comprobar si una cadena está vacía |
| `-n` | comprobar si una cadena no está vacía |
| `<` | comprobar si una cadena es menor que otra alfabéticamente (usar `[[ ]]`) |
| `>` | comprobar si una cadena es mayor que otra alfabéticamente (usar `[[ ]]`) |

#### Operadores lógicos

| Operador | Descripción |
|----------|-------------|
| `&&` | AND: comprobar que ambas condiciones se cumplen |
| `\|\|` | OR: comprobar que al menos una condición se cumple |
| `!` | NOT: invertir el resultado de una condición |

#### Comprobación de archivos y directorios

| Operador | Descripción |
|----------|-------------|
| `-e` | comprobar si existe un archivo o directorio |
| `-f` | comprobar si existe y es un archivo normal |
| `-d` | comprobar si existe y es un directorio |
| `-r` | comprobar si se tiene permiso de lectura |
| `-w` | comprobar si se tiene permiso de escritura |
| `-x` | comprobar si se tiene permiso de ejecución o acceso |
| `-s` | comprobar si existe y tiene un tamaño superior a cero |
| `-L` | comprobar si es un enlace simbólico |

### Ejemplos

#### Condicional `if`, `elif` y `else`
```
    #!/bin/bash

    read -p "Introduce tu edad: " EDAD

    if [ "$EDAD" -ge 18 ]; then
        echo "Eres mayor de edad"
    elif [ "$EDAD" -ge 16 ]; then
        echo "Tienes entre 16 y 17 años"
    else
        echo "Eres menor de 16 años"
    fi
```

#### Condicional `case`
```
    #!/bin/bash

    echo "1. Iniciar"
    echo "2. Configuración"
    echo "3. Salir"

    read -p "Selecciona una opción: " OPCION

    case "$OPCION" in
        1)
            echo "Iniciando..."
            ;;
        2)
            echo "Abriendo configuración..."
            ;;
        3)
            echo "Saliendo..."
            ;;
        *)
            echo "Opción no válida"
            ;;
    esac
```
#### Ejemplos de condiciones y comparaciones

> **Comparaciones numéricas**
>
> | Condición | Descripción |
> |-----------|-------------|
> | `[ "$EDAD" -ge 18 ]` | comprobar si la edad es mayor o igual a 18 |
> | `[ "$NUMERO" -eq 10 ]` | comprobar si el número es igual a 10 |
> | `[ "$NUM" -gt 0 ]` | comprobar si un número es mayor que cero |
> | `[ "$NUM" -lt 0 ]` | comprobar si un número es menor que cero |
> | `[ "$NUM" -eq 0 ]` | comprobar si un número es igual a cero |
> | `(( NUM > 0 ))` | comprobar si un número es mayor que cero utilizando operadores aritméticos |
> | `(( NUM < 0 ))` | comprobar si un número es menor que cero utilizando operadores aritméticos |
> | `[[ "$EDAD" -ge 18 && "$EDAD" -le 65 ]]` | comprobar si la edad está entre 18 y 65, ambos incluidos |

> **Comparaciones de texto**
>
> | Condición | Descripción |
> |-----------|-------------|
> | `[ "$NOMBRE" = "Jose" ]` | comprobar si el nombre es `Jose` |
> | `[[ "$A" == "$B" ]]` | comprobar si dos cadenas de texto son iguales |
> | `[[ "$A" > "$B" ]]` | comprobar si una cadena es mayor que otra según su orden lexicográfico |
> | `[ -z "$NOMBRE" ]` | comprobar si una variable está vacía |
> | `[ -n "$NOMBRE" ]` | comprobar si una variable no está vacía |
> | `[[ "$OPCION" == "S" \|\| "$OPCION" == "s" ]]` | comprobar si la opción es `S` o `s` |

> **Comprobaciones de archivos y directorios**
>
> | Condición | Descripción |
> |-----------|-------------|
> | `[ -f "archivo.txt" ]` | comprobar si existe un archivo normal llamado `archivo.txt` |
> | `[ -d "Documentos" ]` | comprobar si existe un directorio llamado `Documentos` |
> | `[[ ! -f "archivo.txt" ]]` | comprobar si no existe un archivo normal llamado `archivo.txt` |

> **Diferencias entre las estructuras de comparación**
>
> | Estructura | Descripción |
> |------------|-------------|
> | `[ ... ]` | evaluar condiciones mediante el comando `test`; utilizar operadores como `-gt`, `-lt` y `-eq` para números |
> | `[[ ... ]]` | evaluar condiciones con sintaxis ampliada de Bash, incluyendo expresiones lógicas y comparaciones de texto |
> | `(( ... ))` | evaluar expresiones aritméticas mediante operadores como `>`, `<`, `>=`, `<=` y `==` |

> **Importante:**
> - Dejar espacios entre los corchetes y la condición: `[ "$EDAD" -ge 18 ]`.
> - Utilizar `then` para iniciar las instrucciones y `fi` para cerrar el bloque `if`.
> - `elif` y `else` pertenecen al mismo bloque `if`, por lo que solo se escribe un `fi` al final.
> - En `case`, utilizar `;;` para finalizar cada alternativa y `esac` para cerrar la estructura.
> - En `[ ]` y `[[ ]]`, utilizar `-gt`, `-lt`, `-eq`, etc., para comparaciones numéricas.
> - En `(( ))`, utilizar los operadores aritméticos habituales: `>`, `<`, `>=`, `<=` y `==`.
> - En `[[ ]]`, los operadores `<` y `>` comparan cadenas de texto, no números.
> - En expresiones como `(( NUM > 0 ))`, no es necesario escribir `$` delante de una variable numérica.
> - Validar los datos introducidos mediante `read` antes de utilizarlos como números enteros.

### Bucles

Los bucles permiten ejecutar instrucciones repetidamente mientras se cumpla una condición o se recorra una lista de elementos.

| Comando | Descripción |
|---------|-------------|
| `for` | repetir instrucciones para cada elemento de una lista o secuencia |
| `while` | repetir instrucciones mientras una condición sea verdadera |
| `until` | repetir instrucciones mientras una condición sea falsa, hasta que se cumpla |
| `do` | iniciar el bloque de instrucciones del bucle |
| `done` | finalizar el bloque de instrucciones del bucle |
| `continue` | saltar a la siguiente iteración del bucle |
| `break` | interrumpir el bucle y continuar con las instrucciones posteriores |

#### Bucle `for`

Recorrer una lista de valores o archivos.
```
    # Recorrer una lista de números
    for i in 1 2 3 4 5
    do
        echo "$i"
    done
```
```
    # Recorrer archivos con extensión .sh
    for archivo in *.sh
    do
        echo "$archivo"
    done
```
```
    # Recorrer una secuencia numérica
    for i in {1..5}
    do
        echo "$i"
    done
```
#### Bucle `while`

Repetir instrucciones mientras la condición sea verdadera.
```
    count=1

    while [ "$count" -le 5 ]
    do
        echo "$count"
        ((count++))
    done
```
#### Bucle `until`

Repetir instrucciones mientras la condición sea falsa, hasta que se cumpla.
```
    count=1

    until [ "$count" -gt 5 ]
    do
        echo "$count"
        ((count++))
    done
```
#### Control de bucles

| Comando | Descripción |
|---------|-------------|
| `continue` | omitir las instrucciones restantes de la iteración actual y pasar a la siguiente |
| `break` | finalizar inmediatamente el bucle |
| `((variable++))` | incrementar una variable numérica en una unidad |
| `((variable--))` | disminuir una variable numérica en una unidad |

**Ejemplo con `continue` y `break`:**
```
    for i in 1 2 3 4 5
    do
        if [ "$i" -eq 3 ]; then
            continue
        elif [ "$i" -eq 4 ]; then
            break
        fi

        echo "$i"
    done
```
**Resultado:**

    1
    2

**Explicación:**
- `1` y `2`: se muestran normalmente.
- `3`: se omite mediante `continue`.
- `4`: finaliza el bucle mediante `break`.
- `5`: no se procesa porque el bucle ya ha terminado.

> Ejemplos adicionales
> | Comando | Descripción |
> |---------|-------------|
> | `for i in {1..10}` | recorrer los números del 1 al 10 |
> | `for i in {1..10..2}` | recorrer los números del 1 al 10 de dos en dos |
> | `for archivo in *.txt` | recorrer los archivos terminados en `.txt` de la carpeta actual |
> | `for carpeta in */` | recorrer las carpetas visibles de la ruta actual |
> | `while true` | crear un bucle indefinido que necesita una interrupción para finalizar |
> | `until [ "$count" -eq 10 ]` | repetir instrucciones hasta que `count` sea igual a 10 |

> **Importante:**
> - `for` se utiliza principalmente para recorrer elementos o secuencias.
> - `while` ejecuta el bloque mientras la condición sea verdadera.
> - `until` ejecuta el bloque mientras la condición sea falsa.
> - `continue` salta a la siguiente iteración; `break` termina el bucle.
> - Los comandos `do` y `done` delimitan las instrucciones que se repiten.
> - En Bash, si `*.sh` no encuentra coincidencias, normalmente se utiliza el patrón literal `*.sh`, salvo que se configure otro comportamiento.

### Funciones

Las funciones permiten agrupar instrucciones para reutilizarlas dentro de un script, evitando repetir código.

| Comando | Descripción |
|---------|-------------|
| `nombre_funcion() { ...; }` | definir una función que contiene instrucciones |
| `nombre_funcion` | ejecutar una función previamente definida |
| `nombre_funcion <parametro>` | ejecutar una función pasando uno o varios argumentos |
| `$1`, `$2`, `$3` | acceder a los argumentos recibidos por la función |
| `$#` | obtener el número de argumentos recibidos por la función |
| `"$@"` | acceder a todos los argumentos de la función |
| `local <variable>=<valor>` | declarar una variable local dentro de una función |
| `return <codigo>` | finalizar una función devolviendo un código de estado entre 0 y 255 |
| `$?` | consultar el código de salida de la última función o comando ejecutado |

#### Función básica

Definir una función y ejecutarla mediante su nombre.

```bash
my_function() {
    echo "Hola mundo"
}

my_function
```

#### Función con parámetros

Pasar argumentos a una función y utilizarlos mediante `$1`, `$2`, etc.

```bash
my_function_with_params() {
    echo "Hola $1"
}

my_function_with_params "Jose"
```

**Resultado:** `Hola Jose`

#### Variables globales y locales

| Tipo | Descripción |
|------|-------------|
| Variable global | variable de shell definida fuera de una función, accesible desde las funciones del mismo shell |
| Variable local | variable declarada con `local` dentro de una función, limitada a su ámbito y al de las funciones que invoque |

```bash
NOMBRE="Jose"

my_function_2() {
    local EDAD=30
    echo "Nombre: $NOMBRE"
    echo "Edad: $EDAD"
}

my_function_2
```

> **Importante:**
> - Las variables globales pueden utilizarse y modificarse dentro de las funciones.
> - Las variables locales se declaran mediante `local` y no permanecen disponibles fuera de su ámbito.
> - No dejar espacios alrededor de `=` al asignar variables.

#### Función con retorno (`return`)

Finalizar una función indicando si la operación se ha ejecutado correctamente.

```bash
my_function_with_return() {
    return 1
}

my_function_with_return
echo $?
```

**Resultado:** `1`

| Código | Descripción |
|--------|-------------|
| `return 0` | indicar que la función se ha ejecutado correctamente |
| `return 1` | indicar un error o resultado no satisfactorio |
| `return 2` a `255` | indicar otros estados según la lógica de la función |

> **Importante:** `return` devuelve un código de estado, no un dato como una cadena de texto o un resultado numérico cualquiera.

#### Devolver valores mediante `echo`

Para obtener un valor calculado por una función, se puede utilizar `echo` junto con `$(...)`.

```bash
sumar() {
    echo "$(($1 + $2))"
}

RESULTADO=$(sumar 5 3)
echo "$RESULTADO"
```

**Resultado:** `8`

> **Diferencias:**
> - `return` → devolver el estado de ejecución de una función.
> - `echo` → escribir un resultado que puede capturarse mediante `$(...)`.
> - `local` → evitar que las variables internas de una función modifiquen variables externas del mismo nombre.

#### Ejemplo de función con parámetros y retorno

```bash
#!/bin/bash

sumar() {
    resultado=$(( $1 + $2 ))
    return "$resultado"
}

sumar 3 5
echo "Resultado: $?"
```

**Resultado:** `8`

> **Importante:**
> - `$1` y `$2` representan los argumentos recibidos por la función.
> - `return` devuelve un código de estado entre 0 y 255.
> - `$?` permite consultar ese código inmediatamente después de ejecutar la función.
> - No utilizar `return` para devolver resultados matemáticos generales, porque está limitado a códigos de estado.
> - Para devolver resultados numéricos sin esa limitación, utilizar `echo` y capturar su salida mediante `$(...)`.

### Manejo básico de errores

Permitir detectar errores durante la ejecución de comandos y actuar según el resultado.

| Comando | Descripción |
|---------|-------------|
| `mkdir -p "$DESTINO" \|\| exit 1` | crear una carpeta y finalizar el script si falla la operación |
| `cp archivo.txt destino/ 2>/dev/null \|\| echo "ERROR"` | intentar copiar un archivo ocultando el error original y mostrando un mensaje personalizado |
| `$?` | obtener el código de salida del último comando ejecutado (`0` indica éxito y un valor distinto de `0` indica error) |
| `if [ $? -ne 0 ]; then ... fi` | comprobar si el último comando ha producido un error y ejecutar instrucciones si ha fallado |
| `<comando> \|\| <instrucción>` | ejecutar una instrucción únicamente si el comando anterior falla |
| `<comando> && <instrucción>` | ejecutar una instrucción únicamente si el comando anterior finaliza correctamente |
| `exit <codigo>` | finalizar el script devolviendo un código de salida |
| `2> <archivo>` | redirigir los mensajes de error a un archivo |
| `bash -n script.sh` | comprobar errores de sintaxis sin ejecutar el script |
| `bash -x script.sh` | ejecutar el script mostrando las instrucciones procesadas para facilitar la depuración |

#### Ejemplos

**Comprobar errores mediante `$?`:**

```bash
#!/bin/bash
cp file.txt /tmp/
if [ $? -ne 0 ]; then
    echo "Error al copiar el archivo."
fi
```

**Ejecutar una instrucción si se produce un error (`||`):**

```bash
cp file1.txt /tmp/ || echo "Error al copiar el archivo."
```

**Ejecutar una instrucción si no se produce un error (`&&`):**

```bash
cp file2.txt /tmp/ && echo "Archivo copiado correctamente."
```

**Gestionar ambos resultados mediante `if` y `else`:**

```bash
if cp file.txt /tmp/; then
    echo "Archivo copiado correctamente."
else
    echo "Error al copiar el archivo."
fi
```

**Finalizar un script cuando se produce un error:**

```bash
if ! cp file.txt /tmp/; then
    echo "Error al copiar el archivo."
    exit 1
fi
```

> **Importante:**
> - `0` → ejecución correcta.
> - Distinto de `0` → error o resultado no satisfactorio.
> - `||` → ejecutar si falla el comando anterior.
> - `&&` → ejecutar si tiene éxito el comando anterior.
> - `$?` → consultar inmediatamente después del comando, ya que su valor cambia después de ejecutar otro comando.

#### Evitar confirmaciones incorrectas

Cuando falla un comando, Bash normalmente continúa ejecutando las instrucciones siguientes.

**Ejemplo:**

```bash
mkdir -p "$DESTINO" || exit 1

echo "Prueba" >> "$DESTINO/registro.log" || exit 1

echo "Registro creado correctamente."
```

> **Importante:**
> - `|| exit 1` detiene el script si falla el comando anterior.
> - Un mensaje de éxito debe mostrarse únicamente después de comprobar que la operación se ha completado correctamente.
> - `$?` debe consultarse inmediatamente después del comando cuyo resultado queremos comprobar.
> - `bash -n` comprueba la sintaxis, pero no detecta todos los errores que pueden producirse durante la ejecución.

## Cron Jobs (Tareas programadas)

**Cron** es un demonio (servicio del sistema) que permite ejecutar comandos y scripts automáticamente en fechas y horarios programados.

**Crontab** es el archivo donde se definen las tareas programadas de un usuario.

### Gestión de Cron

| Comando | Descripción |
|---------|-------------|
| `sudo systemctl start cron` | iniciar el servicio Cron |
| `sudo systemctl restart cron` | reiniciar el servicio Cron |
| `crontab -l` | mostrar las tareas programadas del usuario actual |
| `crontab -e` | abrir el editor para crear o modificar las tareas programadas |
| `crontab -r` | eliminar todas las tareas programadas del usuario actual. Utilizar con precaución |
| `sudo crontab -l` | mostrar las tareas programadas del superusuario (`root`) |
| `systemctl status cron` | comprobar el estado del servicio Cron en sistemas con systemd |
| `systemctl is-active cron` | comprobar si el servicio Cron está activo |
| `journalctl -u cron --since today --no-pager` | consultar los registros del servicio Cron del día actual sin utilizar el paginador |

> #### Cron en WSL
>
> | Estado del sistema | Comportamiento de Cron |
> |--------------------|------------------------|
> | WSL activo y servicio Cron iniciado | las tareas programadas pueden ejecutarse |
> | Terminal cerrada, pero WSL sigue activo | Cron puede continuar ejecutándose |
> | Distribución WSL detenida | Cron no ejecuta tareas |
> | Windows bloqueado | las tareas pueden ejecutarse si Windows continúa activo |
> | Windows suspendido o hibernando | las tareas no se ejecutan durante ese periodo |
>
> **Importante:**
> - Cerrar la terminal mediante `exit` no garantiza que WSL continúe funcionando.
> - El servicio Cron no mantiene necesariamente activa la distribución WSL por sí solo.
> - Cron no recupera automáticamente todas las ejecuciones perdidas mientras el sistema estaba detenido.
> - Para tareas que deban ejecutarse independientemente de la sesión WSL, considerar el Programador de tareas de Windows.

### Estructura de una tarea Cron

Cada tarea se define mediante **cinco campos temporales y el comando que se desea ejecutar**.

```bash
* * * * * <comando>
│ │ │ │ │
│ │ │ │ └── Día de la semana (0-7, domingo = 0 o 7)
│ │ │ └──── Mes (1-12)
│ │ └────── Día del mes (1-31)
│ └──────── Hora (0-23)
└────────── Minuto (0-59)
```

| Símbolo | Descripción |
|---------|-------------|
| `*` | cualquier valor del campo |
| `,` | separar varios valores concretos |
| `-` | indicar un intervalo de valores |
| `/` | establecer intervalos periódicos |

### Ejemplos de programación

> | Expresión | Descripción |
> |-----------|-------------|
> | `* * * * *` | ejecutar cada minuto |
> | `30 2 * * *` | ejecutar todos los días a las 02:30 |
> | `*/5 * * * *` | ejecutar cada 5 minutos |
> | `0 8,12 * * *` | ejecutar todos los días a las 08:00 y 12:00 |
> | `0 8 * * 1-5` | ejecutar de lunes a viernes a las 08:00 |
> | `0 9-17 * * 1-5` | ejecutar cada hora, desde las 09:00 hasta las 17:00, de lunes a viernes |
> | `0 0 * * 0` | ejecutar ejecutar cada domingo a las 00:00 |
> | `0 9 1 * *` | ejecutar el primer día de cada mes a las 09:00 |
> | `0 9 * * 1` | ejecutar todos los lunes a las 09:00 |
> | `0 0 1 1 *` | ejecutar cada 1 de enero a medianoche |

### Ejecutar scripts mediante Cron

Para programar un script es recomendable utilizar su **ruta absoluta**.

| Comando | Descripción |
|---------|-------------|
| `pwd` | mostrar la ruta absoluta del directorio actual |
| `realpath script.sh` | obtener la ruta absoluta del script |
| `chmod +x script.sh` | conceder permiso de ejecución al script |
| `crontab -e` | abrir la configuración para programar su ejecución |

#### Ejemplo de tarea programada

Ejecutar un script cada 5 minutos:

```bash
*/5 * * * * /bin/bash /home/josed/scripts/script.sh
```

Ejecutar el script y guardar su salida en un archivo de registro:

```bash
*/5 * * * * /bin/bash /home/josed/scripts/script.sh >> /home/josed/scripts/cron.log 2>&1
```

| Elemento | Descripción |
|----------|-------------|
| `*/5 * * * *` | ejecutar cada 5 minutos |
| `/bin/bash` | utilizar Bash para ejecutar el script |
| `/home/josed/scripts/script.sh` | ruta absoluta del script que se desea ejecutar |
| `>>` | añadir la salida al final del archivo sin sobrescribirlo |
| `/home/josed/scripts/cron.log` | archivo donde se guardan los resultados |
| `2>&1` | redirigir también los mensajes de error al mismo archivo |

### Abrir el explorador de archivos

| Comando | Descripción |
|---------|-------------|
| `xdg-open .` | abrir el directorio actual con el explorador predeterminado de Linux, si está disponible |
| `explorer.exe .` | abrir el directorio actual de WSL con el Explorador de archivos de Windows |
| `open .` | abrir el directorio actual en el explorador de macOS |

**Importante:**
- Cron debe estar instalado y su servicio en funcionamiento para ejecutar tareas.
- Cada usuario puede disponer de su propio `crontab`.
- Los archivos de Cron no son scripts de Bash; contienen reglas de programación y comandos.
- En Ubuntu, las tareas de usuario se almacenan normalmente en `/var/spool/cron/crontabs/`, pero deben editarse mediante `crontab -e`.
- La configuración general de tareas también puede encontrarse en `/etc/crontab` y `/etc/cron.d/`.
- Las tareas utilizan la zona horaria configurada para Cron.
- Cron dispone de un entorno de ejecución limitado; conviene utilizar rutas absolutas.
- Los directorios donde se guardan los registros deben existir previamente.
- En WSL, Cron no ejecutará las tareas mientras la distribución esté detenida.

### Redirección de salidas y errores en Cron

Las redirecciones permiten guardar los resultados y errores de las tareas programadas en archivos de registro (`.log`).

#### Diferencias entre las redirecciones

| Sintaxis | Descripción |
|----------|-------------|
| `> cron.log` | guardar la salida sobrescribiendo el contenido anterior |
| `>> cron.log` | añadir la salida al final del archivo, conservando su contenido anterior |
| `2> cron.log` | guardar únicamente los mensajes de error, sobrescribiendo el contenido anterior |
| `>> cron.log 2>&1` | añadir tanto la salida normal como los errores al mismo archivo |
| `> /dev/null 2>&1` | descartar tanto la salida normal como los errores |

#### Explicación de cada elemento

**Ejemplo de tarea programada:**

```bash
*/5 * * * * /bin/bash /home/josed/scripts/script.sh >> /home/josed/scripts/cron.log 2>&1
```

| Elemento | Descripción |
|----------|-------------|
| `*/5 * * * *` | ejecutar la tarea cada 5 minutos |
| `/bin/bash` | utilizar Bash para ejecutar el script |
| `/home/josed/scripts/script.sh` | indicar la ruta absoluta del script que se desea ejecutar |
| `>>` | añadir la salida del script a un archivo sin sobrescribir su contenido anterior |
| `/home/josed/scripts/cron.log` | indicar la ruta del archivo donde se guardarán los resultados |
| `2>&1` | redirigir los mensajes de error al mismo destino que la salida estándar |

#### Ejemplo sencillo

**1. Crear un script llamado `script.sh`:**

```bash
#!/bin/bash

echo "Ejecutado correctamente"
date
```

**2. Programar su ejecución cada 5 minutos mediante `crontab -e`:**

```bash
*/5 * * * * /bin/bash /home/josed/scripts/script.sh >> /home/josed/scripts/cron.log 2>&1
```

**3. Resultado almacenado en `cron.log`:**

```text
Ejecutado correctamente
Mon Oct 19 07:00:00 CEST 2026
Ejecutado correctamente
Mon Oct 19 07:05:00 CEST 2026
Ejecutado correctamente
Mon Oct 19 07:10:00 CEST 2026
```

**4. Consultar el registro:**

| Comando | Descripción |
|---------|-------------|
| `cat /home/josed/scripts/cron.log` | mostrar todo el contenido del registro |
| `tail /home/josed/scripts/cron.log` | mostrar las últimas 10 líneas del registro |
| `tail -f /home/josed/scripts/cron.log` | visualizar en tiempo real las nuevas líneas añadidas al registro |

**Importante:**
- `cron.log` no es obligatorio para ejecutar una tarea programada; se utiliza para conservar sus resultados.
- `>` sobrescribe el contenido anterior, mientras que `>>` lo conserva y añade nuevas entradas.
- `2>&1` redirige los errores al destino de la salida estándar; por sí solo no crea un archivo.
- `/dev/null` permite descartar las salidas que no se desean conservar.
- El archivo `cron.log` se crea automáticamente si no existe, siempre que la carpeta de destino exista y se tengan permisos de escritura.
- Las fechas mostradas en el ejemplo son ilustrativas; las reales dependerán de cuándo se ejecute el script y de la zona horaria configurada.

### Backup automático mediante Cron

Crear un script que comprima una carpeta, añada la fecha al archivo generado y programe su ejecución diariamente.

| Comando | Descripción |
|---------|-------------|
| `date +%Y-%m-%d` | `2026-10-22` | generar un nombre con la fecha |
| `date +%Y-%m-%d_%H-%M-%S` | `2026-10-22_08-54-06` | generar un nombre con fecha y hora |
| `date '+%d/%m/%Y %H:%M:%S'` | `22/10/2026 08:54:06` | mostrar fecha y hora legibles dentro de un registro |
| `mkdir -p <ruta>` | crear la carpeta de destino si no existe |
| `tar -czf <archivo.tar.gz> <carpeta>` | comprimir una carpeta y su contenido en un archivo `.tar.gz` |
| `tar -tzf <archivo.tar.gz>` | consultar el contenido del archivo comprimido |
| `tar -xzf <archivo.tar.gz>` | extraer el contenido del archivo comprimido |
| `crontab -e` | editar las tareas programadas del usuario |
| `crontab -l` | comprobar las tareas programadas |

> **Importante:**
> - Para los nombres de archivos, evitar formatos con `/`, porque representan separadores de directorios.
> - Utilizar fecha y hora cuando sea necesario conservar varias copias durante un mismo día.
> - Guardar los backups fuera de la carpeta que se está comprimiendo para evitar incluir copias anteriores.
> - Comprobar que `tar` ha terminado correctamente antes de mostrar un mensaje de éxito.

#### Ejemplo de script

```bash
#!/bin/bash

ORIGEN="/ruta/carpeta"
DESTINO="/ruta/backups"
FECHA=$(date +%Y-%m-%d)

mkdir -p "$DESTINO"

tar -czf "$DESTINO/backup_$FECHA.tar.gz" -C "$(dirname "$ORIGEN")" "$(basename "$ORIGEN")"

if [ $? -eq 0 ]; then
    echo "Backup creado correctamente."
else
    echo "ERROR al crear el backup."
    exit 1
fi
```

#### Programación diaria a las 02:00

Añadir mediante `crontab -e`:

```cron
0 2 * * * /bin/bash /ruta/backup.sh >> /ruta/backup.log 2>&1
```

**Importante:** en WSL, la distribución debe estar en funcionamiento para que Cron ejecute la tarea.

- incluye variables de entorno necesarias para Git

C:\Program Files\Git>
```

En la práctica los comandos funcionan igual que en CMD, pero Git suele estar mejor preparado para funcionar sin problemas.

## Git Bash

Git Bash es una terminal tipo **Linux/Unix** incluida en Git for Windows.

Permite usar comandos Linux además de Git.

Ejemplo:

```text
usuario@PC MINGW64 ~/proyecto
$
```

Ejemplo de comandos:

```bash
ls
pwd
cd proyecto
git status
```

---

## Comparación

| Terminal | Tipo | Ventajas | Uso recomendado |
|--------|--------|--------|--------|
| CMD | Terminal nativa de Windows | Simple | Uso general |
| Git CMD | CMD con Git configurado | Git funciona directamente | Git en Windows |
| Git Bash | Terminal estilo Linux | Comandos Unix + Git | Recomendado para desarrollo |

---

💡 **Recomendación:** usar **Git Bash** para trabajar con Git desde terminal, porque además de Git permite usar comandos como `ls`, `pwd`, `mkdir`, `cp`, `mv` y `rm`.

# 12. Diagrama visual del flujo Git

```text
[Working Directory]
       |
       | git add
       v
[Staging Area]
       |
       | git commit
       v
[Repositorio Local]
       |
       | git push
       v
[Repositorio Remoto]
```

Resumen:

- **Working Directory**: donde editas archivos
- **Staging Area**: donde preparas los cambios
- **Repositorio Local**: donde se guardan los commits
- **Repositorio Remoto**: GitHub, GitLab o servidor remoto
