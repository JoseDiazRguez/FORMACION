## Commit

Un **commit** es una fotografía o instantánea del estado de nuestro proyecto en un momento determinado.

Git funciona registrando estas instantáneas a lo largo del tiempo.  
Cada commit representa un conjunto de cambios realizados en los archivos del proyecto.

Gracias a los commits podemos:

- guardar versiones del proyecto
- volver a estados anteriores
- revisar los cambios realizados
- entender la evolución del código

---

## Ramas (branch)

Las **ramas** permiten trabajar en diferentes líneas de desarrollo dentro de un mismo proyecto.

Cada rama representa una versión independiente del código donde podemos:

- desarrollar nuevas funcionalidades
- corregir errores
- probar ideas o experimentos
- trabajar en paralelo sin afectar a la versión principal

Por defecto, Git crea una rama principal llamada **main** (anteriormente llamada *master*).

Cuando trabajamos en una rama, los commits que realizamos solo afectan a esa rama hasta que decidimos integrarlos con otras.

---

### Ejemplo visual de ramas

```
main
 │
 ├── Commit A
 ├── Commit B
 │
 └── feature-login
        │
        ├── Commit C
        └── Commit D
```

En este ejemplo:

- **main** contiene el desarrollo principal
- **feature-login** es una rama creada para desarrollar una nueva funcionalidad
- los commits de esa rama no afectan a `main` hasta que se integran

Esto permite desarrollar funcionalidades sin romper la versión principal del proyecto.

---

### Comandos relacionados con ramas

| Comando | Descripción |
|-------|-------------|
| `git config --global init.defaultBranch main` | establece **main** como nombre de la rama principal |
| `git branch -m <nombre_rama>` | cambia el nombre de la rama actual |

## Repositorio de Git

Un **repositorio Git** es el lugar donde se almacena todo el historial de cambios de un proyecto.

Dentro del repositorio se guarda:

- el código fuente
- la documentación
- cualquier archivo del proyecto
- el historial completo de commits

Cada versión de los archivos queda asociada a un commit, que representa una instantánea del proyecto en ese momento.

---

# Crear un repositorio Git en local

A continuación se muestra un ejemplo básico para crear un repositorio Git desde cero.

---

## 1. Posicionarse en el directorio de trabajo

Primero nos situamos en el Escritorio:

```
cd ~/Desktop
```

Para comprobar en qué directorio nos encontramos:

```
pwd
```

Para ver los archivos y carpetas del directorio actual:

```
ls
```

---

## 2. Crear una carpeta para el proyecto

Creamos una carpeta donde estará nuestro proyecto:

```
mkdir "<nombre_carpeta>"
```

Entramos dentro de la carpeta creada:

```
cd nombre_carpeta
```

---

## 3. Crear un archivo de ejemplo

Creamos un archivo (por ejemplo en Python):

```
touch hellogit.py
```

<img width="1226" height="314" alt="image" src="https://github.com/user-attachments/assets/6f2722ce-3cfe-482a-896c-e68c8267d5c4" />

---

## 4. Abrir el proyecto en un IDE

Podemos abrir el proyecto en un editor como **Visual Studio Code** ejecutando:

```
code .
```

Esto abrirá el IDE con el proyecto ubicado en la carpeta actual.

Dentro del archivo `hellogit.py` podemos escribir por ejemplo:

```python
print("Hello Git!")
```

---

## 5. Inicializar el repositorio Git

Para empezar a usar Git en el proyecto ejecutamos:

```
git init
```

<img width="1284" height="312" alt="image" src="https://github.com/user-attachments/assets/cd1bb30c-b558-4da7-9f38-bcda25688a4c" />

A partir de este momento nuestro directorio se convierte en un **repositorio Git** y podremos empezar a registrar versiones del proyecto.

---

## 6. Comprobar el estado del repositorio

Para ver el estado actual del repositorio ejecutamos:

```
git status
```

Este comando muestra:

- archivos modificados
- archivos nuevos
- archivos preparados para commit

---

## 7. Añadir archivos al área de staging

Ahora podemos añadir los archivos que queremos incluir en el próximo commit.

### Añadir un archivo concreto

```
git add <nombre_archivo>
```

### Añadir todos los archivos modificados

```
git add .
```

---

## 8. Crear un commit

Una vez añadidos los cambios al área de staging podemos crear una nueva versión del proyecto:

```
git commit -m "<mensaje>"
```

El mensaje debe describir brevemente los cambios realizados en esa versión del proyecto.
